# 전열·전등 민원 대처

전기팀 현장용 모바일 웹앱입니다. 민원 접수 → 원인 판정 → 안전 조치 → 복구 → 당직일지 기록까지 **예 / 아니오** 버튼만 눌러 진행합니다.
아이폰 Safari 기준으로 만들었고, 홈 화면에 추가하면 앱처럼 열리며 한 번 열어 두면 **신호가 없어도 동작**합니다.

> 보조용 가이드이며 현장 안전 규정이 우선입니다.

---

## 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 뼈대, 아이폰 홈 화면 앱 설정 |
| `style.css` | 디자인 (라이트/다크, 큰 버튼) |
| `app.js` | 화면 그리기, 뒤로가기, 저장, 당직일지 |
| `flow.js` | **흐름 내용 (질문·판정·메뉴 자료)** — 내용 수정은 여기만 |
| `sw.js` | 서비스워커 (오프라인 캐시, 버전) |
| `manifest.webmanifest` | 앱 이름·아이콘 |
| `icons/` | 앱 아이콘 (SVG, PNG 180/192/512) |
| `validate.js` | 흐름 검증 (`node validate.js`) |
| `package.json` | Node가 ES 모듈로 읽도록 하는 설정 + 단축 명령 |

빌드 과정 없음. 정적 파일 그대로 올리면 됩니다. 외부 CDN·폰트·네트워크 요청 없음.

## 내 컴퓨터에서 실행

```bash
python3 -m http.server 8080
```

브라우저에서 `http://localhost:8080` 을 엽니다. (파일을 더블클릭해서 `file://`로 열면 모듈·서비스워커가 동작하지 않으니 꼭 서버로 엽니다.)

같은 Wi-Fi의 아이폰에서 보려면 `http://<컴퓨터 IP>:8080` 으로 열 수 있지만, 이 경우 https가 아니라서 오프라인 저장·클립보드가 제한됩니다. 실제 사용은 아래 배포 방법으로 https 주소를 만드세요.

흐름 검증:

```bash
node validate.js
```

## 1. 배포 (https 주소 만들기) — Cloudflare Pages

저장소(`claude-private`)는 **비공개**로 두고, 사이트 주소만 팀원에게 공유하는 방식입니다. 주소를 아는 사람은 누구나 열 수 있고, 검색엔진에는 노출되지 않도록 `noindex` 설정이 들어 있습니다.

1. <https://dash.cloudflare.com> 에 로그인(무료 가입)하고 **Workers & Pages** 로 들어갑니다.
2. **Create application → Pages → Connect to Git** 을 누르고 GitHub를 선택합니다.
3. 저장소 접근 권한은 **`claude-private` 하나만** 허용하고 **Install & Authorize → Begin setup**.
4. 설정: Project name(주소가 됩니다. 추측하기 어렵게 무작위 문자를 섞기), Production branch `main`, Build command **비움**, Build output directory **`elec-guide`**.
5. **Save and Deploy**. 끝나면 `https://프로젝트이름.pages.dev` 주소가 생깁니다. 이 주소를 팀원에게 보냅니다.

- 이후 `main`에 푸시할 때마다 자동으로 다시 배포됩니다. 흐름을 고쳤다면 `sw.js`의 `VERSION`도 올립니다(4번 참고).
- 접근을 이메일로 제한하고 싶으면 Cloudflare Zero Trust의 Access로 이 프로젝트를 보호할 수 있습니다.

모든 경로를 상대 경로(`./`)로 만들어서 하위 폴더 주소에서도 그대로 동작합니다.

## 2. 아이폰 홈 화면에 추가

1. 아이폰 **Safari**로 배포한 주소를 엽니다. (크롬·카카오톡 내부 브라우저 말고 Safari)
2. 아래쪽 **공유 버튼**(네모에 위쪽 화살표)을 누릅니다.
3. 목록을 내려 **"홈 화면에 추가"** → 이름 확인 → **추가**.
4. 홈 화면의 ⚡ 아이콘으로 열면 주소창 없이 전체 화면 앱처럼 열립니다.

## 3. 오프라인 사용

- 홈 화면 아이콘으로 **한 번 열어 두면** 모든 파일이 아이폰에 저장되어, 이후 전기실·지하처럼 신호가 없는 곳에서도 그대로 동작합니다.
- 메뉴(☰) → **앱 정보**에서 "오프라인 사용 가능"이 보이면 준비 완료입니다.
- 진행 상태는 아이폰에 자동 저장되어, 앱을 닫았다 열면 **이어서 하기 / 새로 시작**을 고를 수 있습니다.
- 새 버전을 배포하면 다음에 온라인으로 열 때 화면 아래에 "새 버전이 있습니다 [적용]"이 뜹니다.

## 사용 요령

- 상단 바: **← 뒤로**(이전 질문으로, 답도 함께 취소) / 현재 단계 / **☰ 메뉴** / **🏠 처음**(확인 후 초기화). Safari의 스와이프 뒤로가기도 같은 동작입니다.
- 💡 노란 말풍선은 탭하면 펼쳐지는 부연설명, ⚠ 빨간 박스는 항상 보이는 경고입니다.
- 안전 조치 화면은 ①→④ 순서대로 모두 체크해야 다음으로 넘어갑니다.
- 마지막 **당직일지 기록** 화면에서 "당직일지 텍스트 복사"를 누르면 일지 형식 텍스트가 복사됩니다.
- 메뉴 → 설정에서 라이트/다크 테마, **화면 켜짐 유지**(지원하는 iOS 16.4 이상)를 켤 수 있습니다.

## 4. 새 민원 가지 추가 방법

내용은 `flow.js`에만 있습니다. `app.js`는 고칠 필요가 없습니다.

**① `flow.js`의 `FLOW`에 노드를 추가합니다.**

```js
// 예: 질문 하나와 판정 하나 추가
Q_NEW: {
  id: 'Q_NEW', type: 'question', stage: '전열',
  title: '새 질문입니까?',
  note: '노란 말풍선 부연설명 (선택)',
  options: [
    { label: '예', next: 'R_NEW' },
    { label: '아니오', next: 'PANEL' },
  ],
},
R_NEW: {
  id: 'R_NEW', type: 'result', stage: '판정',
  badge: 'H. 새 판정',
  warn: '빨간 경고 (선택)',
  body: ['조치 문장 1', '조치 문장 2'],
  next: 'SAFE',
},
```

그리고 기존 노드 하나의 `next`나 `options`에서 새 노드로 연결합니다 (연결이 없으면 검증에서 "도달 불가능"으로 나옵니다).

- 화면 유형: `question`(버튼 2~3개) / `info`(설명 + 다음) / `check`(필수 체크 후 다음) / `result`(판정 배지) / `record`(당직일지)
- 버튼 색: 첫째 `예`=파랑, 둘째 `아니오`=주황, 셋째=회색. `kind: 'alt'` 등으로 바꿀 수 있습니다.
- 층은 `23F`처럼 F로 씁니다 (`23층`은 검증에서 오류).

**② 검증을 실행합니다.**

```bash
node validate.js
```

링크 누락, 도달 불가능한 노드, 기록으로 이어지지 않는 막다른 길, 의도하지 않은 순환(허용: `G_RETRY → G`)을 검사합니다. "검증 통과"가 나와야 합니다.
의도한 순환을 새로 만들었다면 `validate.js`의 `ALLOWED_CYCLE_EDGES`에 추가합니다.

**③ `sw.js`의 버전을 올립니다.**

```js
const VERSION = 'v1.0.1';   // 숫자를 올려야 아이폰이 새 파일을 받습니다
```

파일을 새로 추가했다면 `sw.js`의 `ASSETS` 목록에도 넣습니다.

**④ 다시 배포합니다** (`main`에 푸시하면 자동 배포).
